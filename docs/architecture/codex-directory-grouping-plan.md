# Codex 按工作目录分类实施方案

日期：2026-11-10（Asia/Shanghai）。状态：源码实现、两轴代码审查及源码/合成浏览器验收已完成，运行中网关尚未部署更新。基于网关提交 `f2f0d3763cc68d28bb3494110167832bc398eb0c` 的调用链制定；实现决定与实际验证结果记录在[目录分类记录](../../.agents/notes/implemented/feature/2026-11-10-codex-directory-grouping.md)。

## 已确认的目标

用户已选择：新增“按工作目录”，保留现有“按项目”；第一版完成自动目录分类，项目别名和手动项目组放到后续。

目标是让没有原生项目归属、但有工作目录的 Codex 会话也能按目录浏览。前轮只读检查时，网关的 346 条可见会话分布于 13 个工作目录，但均无原生项目归属；这些数字是当时快照，不是固定验收数据。

用户已授权在新分支实施本方案。实现复用现有聊天列表的样式、控件、折叠组和共享 Web 页面，无新页面或视觉体系设计。

## 第一版的使用方式

在已有“显示方式”下拉框提供三个选项：

| 选项 | 行为 |
| --- | --- |
| 最近交互 | 保留现有列表与置顶行为。 |
| 按项目 | 完全保留现有项目分组语义，包括各接入已有的兼容规则。 |
| 按工作目录 | 按会话记录的完整工作目录分组，与原生项目归属独立。 |

已有用户保留此前选择；没有偏好的用户仍默认“最近交互”。用户选择目录模式后记住该选择。默认值不因一次列表中全部会话未归类而自动改变。

目录组以末级目录名为主标题，以主机/接入名称和记录路径作为辅助信息。路径在窄屏允许折行，不能只依赖悬停才能区分同名目录；组头继续使用可通过键盘操作的 `details/summary`。根目录显示根路径；缺少目录时显示“无工作目录”，放在有效目录组之后。

目录模式的会话行显示目录信息；会话详情和菜单中的“项目”仍表示原有项目归属。切换显示方式保留当前打开的聊天、草稿和搜索/来源/归档条件，不触发会话恢复或项目移动。

## 分类规则

| 场景 | 预期结果 |
| --- | --- |
| 同一接入、同一主机的 `/work/shop` 与 `/work/shop/` | 同组。 |
| 同一主机的 `/work/shop` 与 `/backup/shop` | 不同组；虽然主标题均为 `shop`，路径可以区分。 |
| `/work/shop` 与 `/work/shop/api` | 不同组，不自动寻找 Git 根目录。 |
| 同仓库的两个 worktree 目录 | 不同组，第一版不自动合并。 |
| 不同 SSH 主机，或两个独立 Codex 配置中的相同目录 | 不同组。 |
| 同一默认 Codex 配置的 APP、CLI、IDE 会话处于同目录 | 同组；来源筛选继续独立工作。 |
| POSIX 的 `/work/Shop` 与 `/work/shop` | 不同组。 |
| Windows 的 `C:\Work\Shop` 与 `c:/work/shop/` | 同组。 |
| 原生项目为空但 `cwd` 有效 | 正常进入目录组。 |
| 原生项目存在，但 `cwd` 缺失 | 在“按项目”保留原归属，在“按工作目录”进入“无工作目录”。 |

比较按路径语法处理：明确的 Windows 盘符、UNC、扩展路径使用 Windows 规则；单斜杠 POSIX 路径保留大小写、合法反斜杠和有效空格。只有 `//` 等歧义路径才使用实际目标平台提示；不能根据网关电脑的系统推断 SSH 目标。提示缺失时保守保留原字符串身份。

只进行确定的语法归一化，例如 Windows 分隔符/大小写/扩展前缀和非根路径的尾分隔符。不访问目录，不解析符号链接，不用父目录前缀推断项目，也不对 POSIX 路径无条件去除首尾空格。含 `..` 的路径保留其记录身份，不通过假设符号链接关系把它并入另一目录。原始 `cwd` 始终不改写。

## 后端设计

新增 `bridge/features/sessions/directory_grouping.py`，集中处理路径规则、显示名称和分组身份，使用 Python 标准库。模块提供一个纯函数 interface：

```python
directory_group(cwd, *, scope, target_path_style) -> dict
```

每条列表行新增一个值对象：

```json
{
  "directoryGroup": {
    "key": "服务端生成的稳定分组键",
    "name": "shop",
    "path": "/work/shop",
    "missing": false
  }
}
```

- `scope` 使用客户端族与完整接入/路由主机身份。独立 Codex 使用 `codex:` 路由身份，不能替换为执行协议里的 `native_host=local`。
- `key` 使用带版本的结构化元组编码，例如 `["directory-v1", "codex", routingHost, pathStyle, normalizedPath]`；不以目录末级名、主机显示名或易碰撞的字符串拼接作为身份。
- `path` 是用于展示的原记录路径，`name` 是从对应路径语法取得的末级名。没有有效目录时，`name/path` 为 `null`，`missing=true`，键使用独立的缺失值标记；中文标签由前端翻译。
- 保留 `projectKey`、`projectName`、`host`、会话 ID、来源、权限和所有原生执行字段，不复用目录键作为文件访问或原生项目操作凭据。
- 函数不读取数据库、磁盘目录、Git、认证或原生运行时；输入与输出即可完整测试规则。

接入位置有两处：

1. `Bridge.list()` 在原有 `AppHosts.decorate()` 后添加 `directoryGroup`，覆盖默认本机、独立本机及普通 SSH。
2. `WslEntry.list()` 调用同一函数，覆盖 WSL 直接读取与聚合列表路径。不能只在总聚合出口添加，因为 HTTP 可以直接读取 WSL。

目标平台提示由调用方提供：本机使用本机平台，WSL 使用 POSIX；SSH 在 `RemoteStore.call('list', ...)` 的同一次只读脚本中附加私有 `_targetPathStyle`。缓存保留该提示，网关投影消费后删除，HTTP 不暴露内部字段。该方式不增加 SSH 往返，也不额外探测主机。

`SessionStore` 继续提供当前已有的 `cwd` 与原生项目元数据，不引入对新模块的依赖。它是 SSH/WSL 注入的独立源码，把显示规则留在网关可避免破坏远端自包含要求。

## 前端、缓存与分页

`web/index.html` 新增 `directory` 选项；`web/shell/app.js` 在既有渲染流程中选择原项目分组或 `directoryGroup`，共用会话行与折叠组渲染，不复制一套列表。同步 `web/shared/i18n.js` 中对应文案。

现有 `projectKey` 还被新建聊天用于预选已登记项目，因此该调用及原生会话菜单继续读取原有字段。WSL 旧“按项目”本身包含目录兼容规则，第一版不把旧选项改名为“原生项目”。

排序与加载保持当前契约：

- 目录模式向现有列表请求发送 `order=project`，沿用非置顶的最近交互分页顺序；`directory` 是客户端显示模式，不新增服务端排序协议。
- 每批继续加载 100 条；目录组按已加载会话的最新交互时间排序，组内按现有最近交互顺序排列，时间相同时使用稳定身份排序。
- 下一批中同目录的会话合并进已有组，不重复、不丢失，保留折叠状态。切换模式可以重置列表滚动位置，自动刷新和续页沿用当前锚点/滚动保护。
- 首屏只代表已加载部分，不宣称已列出全部目录，也不为目录分类一次性读取全部历史。第一版组头不新增可能误导的“总会话数”。
- 搜索、来源和归档过滤继续在已有读取链路工作，目录分组只组织过滤后的结果。SSH 暂不可用时保留现有错误与缓存反馈，不阻塞本机目录展示。

目录模式的折叠状态使用独立命名空间，至少包含现有网关/认证范围 `listIdentity`、完整接入身份、显示模式及目录键，避免与“按项目”或其他电脑串用。显示方式偏好也按网关和当前 Codex 入口保存；旧 `list-mode` 仅在新范围首次无偏好时读取，并校验为受支持值，不清除其他客户端偏好。

渲染指纹和目录模式快照包含 `directoryGroup`，避免目录变更后节点仍使用旧信息。旧快照缺少该字段时，不把“尚未加载目录信息”当作“无工作目录”：目录模式等待新的列表响应，其他显示模式继续可用。若新响应仍缺少目录分类元数据，展示该接入不支持目录分类的提示，并保留切回现有列表的入口。

| 2 | 三种显示方式、组名/路径展示、偏好与折叠隔离、分页缓存兼容 | `web/index.html`、`web/shell/app.js`、`web/shared/i18n.js`；必要时小幅调整既有列表样式 |
| 3 | 回归与浏览器验收，修正文档中的分组规则 | `tests/`、`tests/browser/`、`ARCHITECTURE.md`、`web/README.md`及实现决策记录 |

首版范围是 Codex 的默认、独立、SSH、WSL 接入。Claude/DSH 列表不随此次变更改变分类规则。浏览器、iOS/Android 中使用同一网关 Web 页面的入口共享新能力；本方案不要求改写原生壳。

默认复用现有 Web 文件和公开资源 URL，不新增资源请求。若实现时确实拆出新 Web 文件，须同步 `web/assets.json`、固定资源白名单及实际使用该文件的桌面资源清单，保持脚本顺序。新 Python 模块只在网关普通导入，不需作为 SSH 源码注入；若实施改变这一点，再同步 `scripts/gateway-resources.json`，不得通过扩大依赖例外解决分层问题。

## 验收标准

1. **目录规则**：覆盖同目录、同名不同路径、子目录、worktree、空目录、根目录、中文/空格、POSIX 大小写/反斜杠/有效尾空格，以及 Windows 盘符、UNC、扩展前缀；网关与目标系统不同仍正确。
2. **入口一致性**：默认 APP/CLI/IDE 同目录同组；不同独立入口、不同主机不合并；WSL 直接与聚合读取输出一致；SSH 平台标记经过缓存仍有效且不出现在 HTTP 响应中。
3. **项目兼容**：原 `projectKey/projectName` 和 `cwd` 保持原值；切回“按项目”结果与旧行为一致；新建聊天项目预选、原生项目菜单和权限不受影响。
4. **列表行为**：用超过 100 条、跨页交错目录的固定合成数据验证续页、去重、稳定排序、折叠、刷新、搜索、来源、归档与最近模式置顶；缺元数据的旧缓存不会显示假“无工作目录”。
5. **浏览器**：真实执行生产资源的 Chromium/WebKit 390 px 与 1280 px 夹具，覆盖三模式切换、同名目录可辨认、长路径、键盘操作、所选聊天与草稿保留、不同网关/入口偏好隔离。
6. **只读与资源**：验证目录分类不调用线程恢复/启动、原生项目写入、额外 SSH 探测或目录访问；在无本地 `bridge` 包的隔离 Python 验证远端注入源码，运行模块依赖和资源检查。

先运行目录模块与对应列表/前端定向测试，再运行仓库要求的共同回归：`python -B scripts/test-backend.py --source-only`、`npm run test:desktop`、`npm run test:boundaries` 及实际浏览器夹具。实现时以 [测试入口](../../tests/README.md) 确认命令与环境；只加载浏览器脚本不算通过。若触发移动端共享资源构建范围，按既有 CI 门禁执行，不以 WebKit 夹具替代原生编译或真机验收。

现场验收使用当时的只读列表重新统计有效目录，确认所有有 `cwd` 的会话进入相应目录组，缺目录者单列。可以对照前轮 13 个目录的现象，但不把持续变化的真实会话数量写成固定测试断言。运行中网关更新、构建、安装、版本号与发布按后续授权执行，本方案不包含这些动作。
