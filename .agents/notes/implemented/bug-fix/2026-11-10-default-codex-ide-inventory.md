# Agent Note: 默认 Codex 目录中的 IDE 历史与深链接阅读

Status: implemented

## 问题

默认本机入口在存储层已识别 `codex_vscode` 后，仍额外排除 IDE，导致同一 `CODEX_HOME` 中的混合历史无法完整显示，选择 VS Code 来源也返回空列表。此前独立配置接入只放行 `codex:`，默认目录又不能重复登记，因而不能通过添加接入解决。

深链接可能跳过列表加载。前端把缺少 `access` 的会话按旧 APP 显示规则处理，并自动请求激活；原生 owner 缺席时，这会把一次 IDE 历史阅读变成显式恢复请求。

## 决策

列表和可用来源共用 `Bridge.local` 判断：默认与独立本机入口均包含其配置目录内的 APP、CLI、IDE。普通 SSH 继续排除 IDE，WSL 保留独立分类分支。配置注册、目录身份和跨配置列表隔离沿用现有实现。

自动连接依据服务器返回的来源。已确认的 APP 列表行可以与历史读取并行连接；未知来源及缓存列表行先等当前会话的服务器元数据。CLI 和 IDE 阅读只被动跟随 owner，冷恢复仍须明确继续。历史缓存只负责显示，不能触发激活。元数据必须匹配本次打开的 ID、host、代次及 timeline；每次打开最多自动激活一次，激活结果未知也不自动重放。首次读取失败后重试仍可确认 APP 来源并连接。

刷新完成不保证所有列表行都新鲜：未确认的置顶操作会保留旧行。自动连接因此按行识别服务器响应，缓存序列化不携带这一资格。

原生附属关系参与列表可见性：IDE 父会话放行后，其附属聊天归入父会话；普通分支与父会话缺失的聊天继续单独展示。验收比较完整 ID 集合及关系，不能用原列表数量加 IDE 记录数代替。

## 验证边界

回归使用真实 Bridge 和合成 SQLite，以及生产 Web 脚本和隔离请求。后端覆盖混合来源、超过 100 条的分页、搜索、置顶、归档、附属关系、配置隔离和读取/恢复边界；前端覆盖未知来源、缓存、读取重试、迟到响应与激活去重。浏览器用例通过现有 critical 驱动执行，包含 Chromium/WebKit 宽窄视口。

- 后端源码回归：3410 项，53 项因平台或原生执行范围跳过，其余通过。测试环境使用 CI 声明的 `aiohttp` 和 `cryptography` 依赖。
- 前端 Node 回归：1516 项通过、1 项平台跳过。
- 新增浏览器回归：两项场景在 Chromium/WebKit 宽窄视口共 8 项通过；旧代码在同一深链接夹具中失败。

一次中间全量运行出现未改动的 IPC 重连用例导航断言失败；该用例独跑 21 次及最终完整回归均通过。独跑时禁止调用列表入口仍通过，未为此修改 IPC 行为。

源码实现阶段只运行合成验证。后续按用户授权在 Linux 原 systemd 服务中重新部署，沿用配置和密码；已核验 HTTPS 鉴权、真实来源列表及手机尺寸浏览器分页。部署验收只读会话列表，没有发送或恢复会话，临时验收登录已退出。列表放行不扩展运行时发现、owner 核验及发送权限，也不保证缺失的历史文件或原生执行环境可用。
