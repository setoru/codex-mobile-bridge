# Agent Note: 从源会话新建并发送继续消息

Status: implemented

## 问题

在新的 Codex 会话继续旧任务，需要手工复制源会话标题和 ID、确认接入、工作目录及模型，再创建聊天并发送引用消息。普通新建使用项目目录与新建默认配置，不能直接代表源会话的实际 worktree、独立聊天目录或原会话设置。把创建和发送串成两次无关联请求，也会在断网后留下难以区分的重复创建、明确未发送与未知发送。

## 决策

共用会话菜单在“会话详情”下一行提供“从会话恢复”，支持 Codex App 和 Codex CLI 的本机与既有 SSH 接入。菜单捕获被选中的源会话身份；操作开始后切换会话、账号或接入，不能把请求改发给当前聊天。正常流程直接创建、确认设置和发送，成功后刷新列表并打开新会话；用户已离开操作上下文时只保留结果提示，不用迟到响应抢回导航。

首条消息固定为 `读取会话[源会话标题](codex://threads/源会话ID)，继续完成`。沿用已有标题回退规则，转义 Markdown 特殊字符并折叠标题中的换行；远端链接携带原生 `hostId`。正文不随界面语言变化，不附加额外指令。新聊天使用原生命名流程，不复制原标题、不发送命名请求。该操作创建新的空会话，不复制历史、Goal 或待审批状态；读取旧会话和继续执行仍由 Codex 完成。

### 操作记录与并发

共享会话业务模块 `RecoveryCommands` 使用现有创建记录 `creations`，以 `recoverySource` 区分恢复操作，不引入另一套恢复账本。稳定的操作 ID 关联源快照、目标 ID、创建及设置阶段、固定消息和已有发送提交 ID。普通创建入口不能将恢复操作记录当作普通新建回执使用。

操作先在账号／接入的 `OperationGate` 外登记和去重，再由 `_run_recovery` 经原门禁执行实际流程。进行中的重复点击立即取得同一操作状态，状态读取也不排到长时间创建或发送后面；实际写入仍受账号切换与接入门禁约束。发送没有加入只读请求合并。页面重载、重新打开菜单、不同请求 ID 和网关重启都不能绕过源会话的未决操作；已确认完成后，新的明确操作可以再创建一个新会话。

### 源配置与原生执行

读取来源前后核对账号、配置目录、接入与目录身份；源 ID、provider 和实际 cwd 必须与保存元数据一致。配置来自已核验原生状态或保存历史，菜单列表缓存不授予执行能力。读取来源不调用源会话的执行恢复，不切换源 owner，也不为获取配置启动原任务。

显式继承 provider、模型、适用的思考强度、速度档位及已支持的权限预设，保留工作区权限目录；缺少必要证据或自定义权限无法可靠转换时，在发送前停止。权限 profile 必须与有效 sandbox 一致。显式空速度档位与字段缺失分开处理，避免把未知值解释成已确认默认值。目录使用源实际 cwd，包括 worktree 和独立聊天目录，不通过项目分类改成项目根目录。本机 Windows 仅在本机文件身份可核验时接受等价路径；SSH 目标不按网关操作系统解释路径。

来源提供完整 sandbox 策略时，目标的实际工作区目录和网络权限必须一致；只匹配权限预设名称不够。首次发送在已有发送 action lock 内重新核验接入、账号、目录及继承设置，防止创建后到首发前的改选被忽略。

App 复用空会话创建运行时，在返回合法新 ID 后立即记录，再核验创建回执及保存身份。创建进程退出后，打开目标聊天并通过新会话的原 App owner 确认继承设置；首次发送必须等待确认。原 owner ID 不复制到新会话，临时创建运行时不接收 `turn/start`。桌面打开失败属于已创建后的接管阶段，保留目标 ID，后续明确继续仍使用该聊天。

CLI 复用原 daemon、主机及 `CODEX_HOME` 创建原生 CLI 会话。创建期间连接变化会保留已知新 ID 并拒绝把结果绑定到另一连接；原生回执和刷新状态均须通过设置核验。CLI 不转成 App 会话，也不为了创建而打开桌面聊天。

SSH App 通过现有通道注入自包含创建与账号身份源码，在目标端重新核验配置目录、账号和目录身份，返回结构化的开始状态、新 ID 及错误。发送远端创建前即登记可能写入；只有远端明确证明尚未开始，才能解除创建不确定状态。远端错误已经取得的新 ID 仍返回本机记录，不从网关本机配置或目录推测远端结果。

### 失败状态与继续

明确未发送时保留新会话和待发文本，提供“继续恢复”或“继续发送”。创建、设置或发送结果未知时提供核对入口，不重新创建、重写设置或重发消息。已经取得目标 ID 时可以打开新会话检查；创建结果未知且没有可靠 ID 时不伪造跳转目标。

未知设置只通过已有原生状态或保存记录核对，确认匹配后变为明确未发送，仍等待用户主动继续。未知发送复用已有提交记录和新读取的原生消息回执核对。完成回执仅返回结果，不覆盖用户后来在新会话修改的模型或其他设置。原会话保持原有内容、任务、owner、provider、认证与工作目录。

## 验证边界

通过现有 Bridge 完整会话操作入口及原生通信替身验证行为，不把私有 helper 的调用形状作为业务契约。App 专项使用实际临时 Python 子进程承载合成创建协议，并由合成原生 owner 发送快照；SSH App 专项在隔离 Python 中实际执行注入源码，不连接真实 SSH 主机。

已运行的专项：`test_create.py` 26 项（1 项平台跳过）、`test_creation_models.py` 12 项、`test_codex_cli_session.py` 70 项、`test_session_recovery_desktop.py` 4 项、`test_resource_layout.py` 5 项；共 117 项，1 项跳过，其余通过。覆盖源设置传递、早期新 ID 回执、权限与 sandbox 冲突、CLI 连接更换、App 默认模型覆盖后的首发设置、未知设置只读核对、打开失败后同 ID 继续、完成回执保护后续改选，以及 SSH 源码独立执行与原主机链接。对应 Python 语法检查及 `git diff --check` 通过。

本节只记录已实际运行的专项。没有执行真实 Codex App／CLI 写入、真实 SSH 联调、原生手机验收、构建或安装；合成协议与源码回归不能代表这些环境已经通过。

## 影响

App 与 CLI 使用同一个恢复业务流程和共用菜单，保留已有认证、同源、CSRF、文件目录边界、账号门禁和未知写入不重放规则。新增恢复操作记录与现有创建记录共存，读取不会激活源会话。功能不迁移账号、不创建 worktree，也不扩大其他客户端或新接入的能力。
