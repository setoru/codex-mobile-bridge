# Codex 新聊天名称可选

Status: implemented

## 行为

Web 和手机的新建 Codex 聊天表单默认留空名称，适用于 Codex App、本机及 SSH CLI、独立 Codex 配置和 WSL。名称标为可选，切换语言或会话类型不会填入固定标题；手动输入的名称保留。

缺省、空串和纯空格规范成空名。人工名称限制为 120 字，拒绝换行及控制字符。创建时只有人工名称调用原生 `thread/name/set`；空名仍通过普通新线程的 `thread/read(includeTurns=true)` 完成持久化。项目归属、工作目录、模型和账号核验，以及创建 UUID 和未知结果不重放规则保持一致。

## 原生名称与显示

标题生成由原生客户端负责。Bridge 不创建标题临时会话、不发送额外模型请求，不维护自动命名任务或回执；发送、被动阅读和通知流程均不附加命名操作。

界面优先显示原生名称，无名称时使用原生内容预览，都没有时显示“未命名聊天”。原生 CLI 与 WSL 接收 `thread/name/updated` 事件后刷新标题，并保留较新名称，避免在途旧读取覆盖。手动命名仍使用原有原生元数据接口及能力限制，不改变会话的 owner、provider、认证、工作目录或执行设置。

## 验证

使用已有测试环境执行与创建、发送、原生标题同步、HTTP、资源及模块边界相关的后端回归，共 343 项，1 项 Windows 专属用例按环境跳过，其余通过。其中 `test_native_chat_titles.py` 通过真实网关调用路径和合成 CLI/WSL 运行时，验证首条消息只使用原线程、不附加命名请求，以及原生名称/预览、人工名称和 UUID 幂等。

`npm run test:desktop` 共 1,525 项，1,524 通过、1 项跳过。新建名称浏览器用例在 Chromium/WebKit 的宽窄视口四种组合均通过，覆盖默认留空、语言与类型切换、手动名称、取消和未知创建重试。

模块边界与 `git diff --check` 通过，保留既有 22 条依赖例外。没有执行真实客户端操作、构建、安装或发布；源码模拟和浏览器夹具不代表原生客户端联调。

## 运行中的网关验证

现场页面曾继续返回旧的“请输入 1–120 字的聊天名称”。原因是静态资源已从磁盘读取新版本，但网关 Python 进程仍从 11 月 10 日持续运行，驻留旧的创建校验。使用已认证的空名加无效会话类型请求复现；无效类型保证探针不能创建真实聊天。当前源码会进入“未知聊天类型”校验，旧进程则提前拒绝空名，公网与本机的实例身份一致。

核验账号切换空闲、网关仅持有字节代理且没有自有终端进程后，已协作重启 `codex-mobile-bridge.service`。同一探针随后通过空名校验；核对新网关实例、公网路由，以及原 Codex/隧道进程和配置未变。此次仅重新加载网关，没有创建聊天、发送模型任务或停止原生 Codex。后端 Python 修改需要重启网关生效，刷新网页只会更新静态资源。
