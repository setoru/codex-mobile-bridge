# Agent Note: 从会话恢复作为普通新建与首发快捷入口

Status: implemented

## 用户要求

从源会话取得信息，在同一接入和主机的新聊天中发送固定首条消息，仅沿用实际工作目录和模型设置。权限直接使用普通新建默认值，无须选择或读取源权限。源会话不需要连接；删除完整配置、认证环境证明及恢复专属核对步骤。

## 行为契约

- 点击菜单时读取一次源标题、ID、实际 `cwd`、模型、思考强度和已知速度档位，不在打开菜单时预取配置。已有原生连接只提供信息，不被启动、停止或切换。
- 新建使用原实际目录，包括 worktree 和已有独立聊天目录；不将其替换成项目根，也不新建目录。没有目录时明确失败。模型缺失时使用原生新建默认并提示；缺失的思考强度和速度参数省略，显式空速度档位保留。
- 提供商、认证、权限、审批、工作区授权目录和其他设置由当前接入的普通新建决定。创建及模型更新不传入源权限字段，也不比较新旧沙箱。
- 创建成功取得 ID 后打开新聊天，保存固定 `读取会话[源会话标题](codex://threads/源会话ID)，继续完成` 为普通草稿，调用普通发送流程自动尝试一次。名称由原生客户端生成，历史、Goal 和待审批状态不复制。
- 首发明确未提交或模型/连接尚未就绪时，在新聊天保留文本与错误，用户使用普通发送继续。未知消息交普通消息管理处理，不重新创建或自动重放发送。用户离开原导航后不抢回界面或发到其他聊天。
- 普通创建与发送继续保留同一请求 ID 的去重和已知目标 ID；新的明确请求可再从同源创建，不扫描同源旧未决恢复来阻止新建。
- 支持默认/独立 Codex 接入中的 App、CLI、IDE 及 WSL，SSH 保持所选已登记主机。能力由接入明确报告，其他客户端不扩展。

## 实现

公开 `/api/sessions/<source-id>/recover` URL 保留。POST 仅需创建 `id`，源信息从服务端读取，不接受客户端传入目录、模型、程序或认证覆盖。旧 `sourceContext` 字段仅为请求兼容而接受，内容不用于选择或校验源配置。GET 携带请求 ID 时只读取对应创建回执；没有 ID 时不寻找同源旧操作，也不启动源会话。

`RecoveryCommands` 仅维护一次普通创建的回执，不发送消息。App/CLI 使用已有 `create_empty` / `CliSessions.create`；WSL 复用自身普通创建的写锁、接入核验、原生 start/read 和目标安装。已知目标上的模型应用复用普通 App 创建收尾，只更新模型、思考强度和速度。已记录的创建与未知模型写入不自动重做。

前端菜单仅保留忙碌与错误，创建成功后退出菜单进入聊天页。自动首发与手动发送共用普通 composer；创建回执中的普通草稿账号身份可用于保存目标草稿，身份缺失或存储不可用时使用已有临时草稿回退，不把已创建聊天留在恢复菜单。

登录、Origin、CSRF、接入启用、账号切换互斥、目录/文件访问限制以及目标原生 owner 和连接身份规则沿用普通创建/发送。本次删除的是源会话权限与认证配置的特殊前置，不放宽公共请求规则。

旧恢复记录只读保留。其已发送或未知发送不会据新回执再次自动首发，源快照里的旧权限不重写到目标。
